# 业务人员维护产品分类

本机入口：http://localhost:1337/admin → Content Manager → Collection Types → **产品分类**。

## 新增与编辑

1. 点击 Create new entry，填写英文分类名称，以及可选的法语、阿拉伯语和中文管理名称。法语或阿拉伯语留空时使用英文；中文只供后台识别。
2. 选择房屋 / 电气设备。房屋的菜单分组选择“不分组”；电气设备可选择变压器、开关设备、变电站或不分组。
3. 检查分类网址标识，仅用小写英文、数字和短横线。网址标识、所属大类和分组首次保存后固定，避免旧链接失效。需要换位置时，新增目标分类，再迁移产品。
4. 设置显示顺序，数字越小越靠前。电气设备分组按其最靠前分类的顺序排列，组内再按顺序排列。
5. Save 只保存草稿，Publish 才同步到网站。发布后通常约 30 秒刷新缓存，首次请求可能先看到旧版本，再刷新即可。

分类名称、顺序和显示状态同步到顶部产品菜单、产品页左侧 Product families、首页分类入口、分类页标题与产品卡片、询盘分类选项。页面布局及两大类名称仍由代码维护。所有语言名称在一张表单维护，无需切换后台语言。

新分类发布后，到 Product 中选择“所属产品分类”，保存并发布产品的相应语言。没有产品的已发布分类显示“产品资料准备中”及联系入口，不自动产生商品。

## 隐藏与删除

- 暂时不展示：关闭“在菜单中显示”，再 Publish。菜单和分类选项收起，已发布分类页、产品详情原网址保留，产品仍可在所属大类完整列表中浏览。
- 永久删除：先迁移全部关联产品，包括所有语言、草稿和已发布版本，再删除分类。有关联产品时，删除或取消发布会提示并阻止操作。
- 产品迁移只保存草稿时，旧的已发布版本仍属于旧分类，需要发布后才完成迁移。
- 取消发布会关闭分类公开页面；有产品时请使用隐藏。删除或取消发布的分类不会在 CMS 重启后自动恢复。

旧的 `substations`、`mv-distribution`、`lv-distribution` 等归类继续兼容，无需批量改产品。首次启动只导入现有 16 个分类，其中太阳能房保留原网址并默认隐藏；不会重写或重新发布已有产品。

## 权限

Super Admin 可直接操作。已有 Operations 等角色的人工权限不会被启动流程覆盖；管理员需到 Settings → Administration panel → Roles，为“产品分类”授予读、创建、编辑、删除、发布及可见字段权限，并保留 Product 的分类字段和发布权限。内部 `key` 由系统生成，无需开放给业务编辑。

## 发布与回退

本次为兼容扩展：新增 `product_categories` 表，把 Product 的 `categoryKey` 从固定选项改为字符串，沿用原列和已有数据。分类 API 只允许匿名读取已发布内容，写入沿用后台账号权限。

部署前按现有流程备份数据库、记录版本，并构建更新 CMS、Web。新 Web 连接尚未升级的 CMS 时，只有分类 API 返回 404 才临时使用旧分类；空数组表示确实没有公开分类，不会恢复默认数据。其他接口错误正常报错。

回退应用时可恢复前一版镜像，保留新增表及数据；旧 Web 只认识原固定分类，新建分类及其产品在旧版不会显示。不要自动删除分类表、清空分类键或重新导入产品。完整恢复新分类功能需重新运行本版 CMS 和 Web。

验证：`node --test apps/cms/tests/product-categories.test.mjs apps/web/tests/product-categories.test.mjs`。本机联调还应检查真实后台 Save / Publish、隐藏后原网址、有关联产品时的删除保护和业务账号权限。
