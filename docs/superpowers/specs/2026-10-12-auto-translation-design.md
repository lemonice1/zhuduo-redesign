# 自动翻译与同步发布

用户确认：只填写一种语言，自动翻译并发布其他语言。当前没有翻译 API；实现可配置的 Chat Completions 兼容接口，默认关闭。实际启用需要用户在 VM 设置自己的服务地址、模型和密钥。

管理员在 Content Manager 点击发布时，以当前语言草稿为源，翻译到 Internationalization 已添加的其他语言。同一 `documentId` 的目标语言草稿会被更新并发布，已有人工译文也会覆盖；不对整站历史内容执行批量回填。适用 Product、Project Case、Article、Certificate、FAQ 和 Site Setting。询盘、内部备注、管理员账户和媒体文件不发送到翻译接口。

使用 Strapi 5.57.0 原生 Document Service 中间件，不新增公开写接口。后台请求必须有管理员 ability；初始化 seed 和无后台权限上下文的内部操作不触发。自动生成的目标语言使用原生 `update({documentId, locale, data})` 创建缺失版本，并继承 Strapi 的非本地化字段复制规则。Strapi 将 UID 字段视为本地化，因此缺失语言须另外复制源 slug，已有目标 slug 保持原值；复制也检查字段权限。AI 只返回文本数组，服务端按已知字段路径还原，JSON 键、数字、slug、图片和排序不会由 AI 修改。创建者和编辑者使用原生 `setCreatorFields` 写入。

源语言和所有目标语言都检查 Content Manager 的读取、创建/编辑、字段及发布权限；任何目标权限不足均终止。所有翻译通过格式校验后，在同一数据库事务内写入并发布源语言及目标语言；接口失败、超时、格式错误、模型校验或数据库失败都回滚本次发布，保留旧的线上版本。内部目标发布用异步上下文标记，避免递归翻译。

配置只注入 CMS，不暴露给前台。启用后配置缺失在发布时返回中文错误，不影响后台正常启动。接口请求限时 30 秒，单条内容的文本总量最多 20,000 字符，最多 1,000 个文本片段。发布过程中目标草稿被其他人修改时中止，避免覆盖新编辑。取消发布继续使用原生单语言行为。

验收用本地 HTTP 翻译服务验证真实网络协议和出错场景，使用 Strapi 原生 middleware manager、Content Manager permission checker 与真实 CASL ability 验证跨语言权限与调用流程。运行全部现有测试、CMS 构建以及 Compose 配置检查；真实翻译质量需要用户配置接口后验收。

用户随后报告中文 FAQ 缺失，VM 实查英文已发布 4 条、中文 0 条，均为原始演示记录。开发模式且 `SEED_DEMO_CONTENT=true` 时先确保 en/zh-Hans 内容语言，再给完全匹配原始英文问答且没有中文草稿/发布版的记录补齐静态中文译文并发布。使用原 documentId、原生事务，不覆盖人工编辑，不需要外部翻译接口；生产模式关闭。
